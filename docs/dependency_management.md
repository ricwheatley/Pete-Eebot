# Dependency management and security review

## Authoritative workflow

`pyproject.toml` is the only hand-edited dependency input. Runtime constraints
belong in `project.dependencies`; test, audit, build, and publishing tools belong
in the `dev` dependency group. Do not add another requirements or constraints
file.

`uv.lock` is generated by uv 0.12.5 and must be committed. It is a universal
lock: it records exact versions, Python/platform markers, distribution URLs,
and SHA-256 hashes for the complete runtime and development graph. It also
requires coverage for the supported deployment/development targets:

- Linux x86_64 (CI and production hosts);
- Linux aarch64 (the documented Raspberry Pi profile);
- Windows AMD64 (local development).

Pete-Eebot declares Python 3.11 through 3.13. CI covers the minimum and maximum
supported minors; the reference Ubuntu deployment uses Python 3.11. uv's
universal lock preserves any Python-specific branches rather than maintaining
separate platform files.

The workflow follows uv's documented separation between a broad project input
and an exact cross-platform lock, frozen syncs, development groups, and
`--no-editable` production installs:

- <https://docs.astral.sh/uv/concepts/projects/layout/>
- <https://docs.astral.sh/uv/concepts/projects/sync/>
- <https://docs.astral.sh/uv/guides/migration/pip-to-project/>

## Install and verify

Development and CI:

```bash
uv lock --check
uv sync --frozen --no-editable
.venv/bin/python -m pip check
.venv/bin/python -m pip_audit --local --skip-editable
```

Production uses a separately provisioned uv 0.12.5 executable so exact syncing
cannot remove the tool that performs the sync:

```bash
/opt/myapp/shared/uv-tool/bin/uv lock \
  --project /opt/myapp/current --check
UV_PROJECT_ENVIRONMENT=/opt/myapp/shared/venv \
  /opt/myapp/shared/uv-tool/bin/uv sync \
  --project /opt/myapp/current --frozen --no-dev --no-editable
/opt/myapp/shared/uv-tool/bin/uv pip check \
  --python /opt/myapp/shared/venv/bin/python
```

Both paths consume the same `uv.lock`. CI additionally installs the locked
development group; its runtime packages are the same exact versions used by
production. Deployment must never resolve from the broad constraints or install
the project editably.

## Updating dependencies

1. Edit direct constraints only in `pyproject.toml` and explain the reason in
   the change review.
2. Run `uv lock --upgrade-package <name>` for a targeted update. Use
   `uv lock --upgrade` only for an intentional whole-graph refresh.
3. Review `git diff -- pyproject.toml uv.lock` and `uv tree --frozen`. Investigate
   every unexpected package, index, source distribution, or marker branch.
4. Run `uv sync --frozen --no-editable`, `python -m pip check`, and
   `python -m pip_audit --local --skip-editable` from the synced environment.
5. Run the unit, real-framework contract, installed-wheel, CLI, and API smokes
   documented in `docs/testing.md`.
6. Recreate two clean environments from the lock and compare sorted
   `importlib.metadata` name/version fingerprints. Compare the same operating
   system and Python version; platform-only packages legitimately differ across
   supported platforms.
7. Commit `pyproject.toml` and `uv.lock` together. Never edit `uv.lock` by hand.
